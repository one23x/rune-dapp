# Rune 项目征程(Journey)

> 这里是项目的**共同记忆**:阶段目标、每日进步、踩坑经验。人和智能体(Claude/subagents)都从这里快速上手、对齐方向。
> 与 `docs/ops/` 的分工:ops 是**操作层**(PROGRESS 进度源 / RUNBOOK 操作手册 / memos 反复问题),journey 是**战略与成长层**(我们要去哪、走到哪了、学到了什么)。

## 结构

| 文件/目录 | 内容 | 谁写 | 何时写 |
|---|---|---|---|
| `ROADMAP.md` | 阶段目标与里程碑(勾选制) | 老板定方向,agent 维护状态 | 阶段启动/完成时 |
| `daily/YYYY-MM-DD.md` | 每日战报:做成了什么、数据、明日重点 | 当天干活的 agent 收尾时写 | 每个工作日收尾 |
| `LESSONS.md` | 编号经验库:问题→根因→方案→可复用经验 | 谁踩坑谁记录 | 踩坑修复后立即 |

## 使用规范(给智能体)

1. **会话开始**:读 `ROADMAP.md` 当前阶段 + 最近 1-2 篇 `daily/`,知道现在打到哪了。
2. **遇到问题先查** `LESSONS.md`(grep 关键词)和 `docs/ops/memos/` —— 大概率前人踩过。
3. **修完一个非平凡问题**:在 `LESSONS.md` 追加一条(编号递增,格式见文件头),一句话讲清根因和复用方法,不写小作文。
4. **收尾**:把当天成果写进 `daily/`,里程碑达成就去 `ROADMAP.md` 打勾(PROGRESS.md 照旧是 Stop-hook 推 Slack 的进度源,两边都要更)。
5. **写给未来的读者**:假设读者(人或 AI)完全没有今天的上下文 —— 地址、分支名、文件路径写全。

## 快速入口

- 现在处于哪个阶段 → [ROADMAP.md](./ROADMAP.md)
- 昨天发生了什么 → [daily/](./daily/)
- 这个坑踩过吗 → [LESSONS.md](./LESSONS.md)
- 怎么操作生产/部署 → `../ops/RUNBOOK.md` 与 `../ops/memos/`
