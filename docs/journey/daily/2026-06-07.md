## 🤖 晚间追加:HL 跟单 AI 排序器(hl-copy-ranker)训练→部署→接入全跑

**意义**:平台第一个**真正训练并上线服务**的自研 ML 模型。此前训练管线长期「饿死」(signal_trades 决议=0,quant-meta-stacker/pm-outcome-cls 从没真训过)。今天用 `trading.hl_copy_signals`(leader 真实成交流,每天数十万条)的 FIFO round-trip realized PnL 作天然标签,把跟单决策从「纯镜像 + 规则门槛」升级为「数据驱动的盈利概率评分」——为内测后的风控升级(Phase 2)铺第一块砖。

**全链路**(一气呵成,中途遇坑即修):
1. **数据**:`export_hl_training_set.py` 全表 mainnet → S3 `gold/hl_copy/v=20260607`,**10340 样本,43.9% 正例**,12 维因果特征(防泄漏:特征只用开仓时刻已兑现的 leader 战绩)。
2. **训练**:撞上**账户级 SageMaker 训练配额 = 0**(全新账户),云端 pipeline 首跑 TrainRanker 失败。改 `train_hl_local.py` 本地 XGBoost 几秒训完:**test AUC = 0.6572**(基线 0.5),logloss 0.6566 < 0.6910 → **证明 HL 跟单数据确有可学习的盈利信号**。Top 特征:leader 在该币的经验厚度 / 是否主流币 / 持仓名义额 / leader 滚动胜率,全部符合交易直觉。
3. **部署**:本地模型 → SageMaker 格式 → **serverless endpoint `hl-copy-ranker`**(InService;serverless 不吃训练实例配额,按调用计费)。
4. **接入**(one-agents 61c47bf + 84f14f9):`hlCopyRankerScore()` 推理 + `hl-copy-ranker-features.ts` 线上复刻同套 FIFO 特征 + copy-executor 每条开仓信号算一次 P(盈利)。**默认 shadow**(`HL_COPY_MIN_RANKER_SCORE=0`,只记 `ai_inferences` 不拦单),验证线上特征与训练对齐后再上调开 gate。**已线上验证分值落库:0 错误,延迟 80-120ms**(xyz:CRCL 0.42 / HYPE 0.17)。

### 🔬 06-08 复盘修正(重要,别被单切分 AUC 骗了)

开 gate 0.45 后用**多模型对比 + 时间序 6 折 CV** 严格复核,推翻了乐观结论:
- **单切分 AUC 不可信**:同一 binary 模型不同切分 AUC 在 **0.43~0.75** 间跳(CV 均值 **0.590 ± 0.115**,**有一折 <0.5**)。早先的 0.657 是冻结切分运气。根因=按单笔 round-trip 建模、行高度自相关、标签近噪声(`export_hl_leader_edge.py` 早写过这警告)。
- **PnL 加权稳定略优**:CV 0.620 vs 0.590,且高分档**正期望**(+$83/单)vs binary 高分档每单 **−$251**——直接修正「肯单优化胜率却拦掉肥尾赢家」。
- **处置**(老板拍板「回退 shadow + 换 v2」):生产 endpoint 换成 **`hl-copy-ranker-v2`**(PnL 加权),`HL_COPY_MIN_RANKER_SCORE` **回退 0(shadow,不拦真单)**。重开 gate 前提=CV 各折稳定 >0.5 或换 leader-edge 聚合模型。
- 配套:worker `ranker-eval.timer`(每日 09:00 UTC)写 `trading.ranker_eval_daily`,持续盯放行 vs 拦截档真实胜率/期望。
- **教训**:任何要拿去拦真钱的模型,**必须 CV 报 mean±std,单切分一律不算数**。
